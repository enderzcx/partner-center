# x402 Fuji 收款接入

2026-09-18，Ender 对“把模拟支付接成真实测试网付款流程”回复“做吧”。沿用伙伴中心受控单商家/单推广者演示，原有两笔完成订单和回执保留。

## 本轮结果目标

商家创建10 USD测试订单，付款钱包通过x402 v2签署10测试USDC付款授权，第三方facilitator提交到Fuji，服务独立核验最终到账，随后复用BeefAPI专用测试库的订单/锁定比例/佣金逻辑，自动支付1测试USDC佣金并回写账本。付款钱包签名需由钱包持有人完成，不由宿主代签。既有出款签名钱包继续仅用于佣金付款。

## 确定的边界

- Fuji43113、Circle测试USDC；收款到当前结算合约 `0x5c905e43e0BB381534530d5e05DF56ab1f420899`。此为测试资金演示，10 USDC到账后1 USDC返佣，剩余9 USDC留在演示合约。不扩展正式商家财务归集方案。
- x402 v2 exact/EIP-3009，PAYMENT-REQUIRED、PAYMENT-SIGNATURE、PAYMENT-RESPONSE。默认facilitator为PayAI，2026-09-18只读supported端点已确认支持eip155:43113。
- 沿用已登录商家创建/支付测试订单，推广者只管理自己的钱包和收益；无账号Agent入口、真实AI推理调用、主网和生产充值余额不在本轮。
- x402开启后禁止模拟支付接口绕过付款。旧已完成模拟订单保留历史。钱包付款前显示明确测试USDC数量，不使用“不会扣款”的旧模拟文案。
- 仅在付款最终确认后发放佣金。签名授权、链上收款、来源入账三个阶段持久化；超时/重启用原授权恢复，不要求再付一笔。不执行自动退款，异常单保留状态供核对。
- 官方SDK兼容性、本地真实EVM授权转账、异常恢复、权限负向、页面桌面与窄屏检查通过后，才能升级受控公网演示；公网最终验收另需付款人签名。

## 协作者边界

后端worker只写收款与持久化、最小路由集成和测试；前端worker只写现有页面付款交互；主会话拥有协议核对、集成、独立验证、部署配置、秘密和真实浏览器/资金操作。两个worker基于4ea7442，均禁止推送/部署或使用真实凭据。
