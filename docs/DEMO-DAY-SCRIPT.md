# 伙伴中心三分钟演示稿

前7页约180秒；第8–11页为问答备用。截图采集于2026-09-19，回看9月18日已完成Fuji测试订单。

## 1. 面向 AI API 服务商的伙伴中心

25秒｜大家好，我们是 BF Labs。我们在做面向 new-api、sub2api 部署者的伙伴中心，通过适配器连接已有网关和业务账本，把伙伴佣金交给链上结算。BeefAPI 是首个已验证的测试场景。标准适配和多产品能力会按具体版本逐步验证。

## 2. 同一笔订单，10 × 10% = 1

30秒｜下面回看一笔已经完成的 Fuji 测试订单。用户通过 x402 支付了10个测试USDC，下单时锁定10%的返佣比例，所以产生1个测试USDC佣金。比例由业务规则决定，不是结算合约自己判断。截图中这一笔有实际测试币收款。

## 3. 收款、返佣、账本对应起来

35秒｜这张回执不仅写着成功，还关联了业务单、收款交易和佣金出款。系统核验链上到账，再完成原账本回写。此前实测遇到批量交易，我们修正识别逻辑后恢复了原付款，没有让用户再付一次。这里是两笔交易，不是收款时原子分账。

## 4. 推广者自己核对收益

25秒｜切到推广者视角，他可以看自己的收益和到账记录，不用只等商家发转账截图。这里累计3个测试USDC对应三笔历史出款，我们今天讲的是最新的1个。前两笔是模拟付款订单驱动的测试币出款，不能当作三笔真实x402订单。

## 5. 已验证与下一步分开讲

25秒｜亮起的是已经验证的链路。下一阶段，我们希望把最终确认的佣金固化为有资金支持的领取权。新版权益合约已经通过本地测试，但还没部署Fuji，也没有切换线上执行器。我们会先验证接入，再逐步走向真实业务。

## 6. 可定制的伙伴结算 L1

25秒｜我们的核心，是把佣金承诺逐步变成有资金支持、条件明确的链上收益。下一阶段会探索让 Avalanche L1 更深地服务这些结算规则。计划提供常用配置包，有专属需求的商家可以定制规则并获得部署协助。原生 new-api、sub2api 适配和 L1 原型都还在路线中。技术基础：https://build.avax.network/docs/avalanche-l1s/evm-configuration/customize-avalanche-l1 。配置包减少重复配置，验证者、资产和升级责任仍需明确。

## 7. 寻找共同验证的项目

15秒｜我们希望找到两到三个 new-api、sub2api 服务商，一起验证版本适配、佣金权利和专属部署需求。计划通过 MCP，让商家和伙伴自己的 Agent 也能查询收益、辅助合作。谢谢。

## 8. 问答：为什么0 AVAX仍有10 USDC？

问答备用｜概览的Value是这笔外层调用携带的AVAX数量。USDC是代币，要看USDC合约发出的Transfer日志。这里index1的原始金额是十六进制989680，也就是一千万；USDC六位小数，所以是10个测试USDC。付款钱包、收款合约、代币地址和金额都已复核。

## 9. 问答：产品价值与当前边界

按问题选择回答，不逐条朗读。先说当前能力，再说限制。被问到新合约时，强调本地验证不等于Fuji部署或审计。被问到营收、增长与资助时，不把测试币、项目提交和发展规划说成商业成果。

## 10. MCP：让自己的Agent协助合作

20秒｜我们计划通过MCP，让用户已有的Agent查收益、看规则和回执，再读取合作资料、准备带推广链接的内容。发布需要用户授权，效果要靠真实数据验证。这是发展方向，当前还没有上线Agent自动推广。

## 11. 预制 L1 配置与商家专属部署

问答备用｜这三个是拟议配置包方向，不是现成产品。包内计划包括参数、网络配置、检查脚本及备份升级说明。业务规则先在协议合约中实现，网络费用与准入在 L1 配置中分别处理。已有链可以继续使用，不要求每家商家都建链。规则更新不能悄悄重写已有佣金，准入和升级也必须交代原权利如何领取。
