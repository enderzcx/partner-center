# 独立佣金结算首版 · 本地实现合同

2026-09-18，依据当前任务中 Ender 确认的「独立结算」「Fuji 测试闭环」及「做吧」。

## 已批准范围

独立应用拥有商家工作台、推广者收款设置和结算回执。BeefAPI 是首个接入方，既有佣金规则和原始余额继续由 BeefAPI 拥有。结算服务接收已冻结的结算单，不重复计算佣金。首版只有一个商家和一个演示推广者；页面身份切换是本机测试工作区，不作为生产身份认证。

当前阶段为 promotion-candidate 本地实现，非生产系统。x402、AA、主网、多商户、市场撮合、推广归因、退款政策变更均不在首版。公网部署、DNS、Fuji 合约发布及转账需要分别授权并配置测试签名环境，本轮不执行。生产凭据和数据禁止使用。

## 模块与写入范围

- 独立项目：本目录。Bun + SQLite 单进程、静态网页、viem EVM 接口、有限权限 ERC20 出款合约。
- BeefAPI：独立 codex/fuji-settlement 工作树，仅增加默认关闭且专用鉴权的测试适配接口与冻结/完成记录。
- 本地验证：真实本地 EVM 合约部署、测试代币转账、重试恢复、数据库事务和浏览器。
- Fuji：只实现配置和运行说明，未配置/未授权不能声称链上通过。

## 资金与恢复约束

金额在接口为整数字符串 USDC 最小单位，计算使用 bigint，账本约束金额上限。原佣金账本只允许可用余额冻结，冻结后不能消费。结算单固定收款地址、金额、来源和唯一编号。合约同编号只能支付一次。

服务在广播之前持久化已签名交易及其哈希。状态 reserved → prepared → broadcast → confirmed → completed。prepared/broadcast 遇到不明结果，保留冻结并仅重播同一原始交易；confirmed 只恢复原账本回写。明确 reverted 标为 blocked，保留冻结交人工核查，不自动换号重付或解冻。一个进程、一个独占执行钱包、串行 nonce，无后台多副本承诺。

链上完成需核对网络、合约、代币、成功 receipt、付款事件、收款地址、金额、编号和代币 Transfer。暂停阻止新签名/广播但仍核验已发出交易和补回写。

本地 fixture 来源仅合成测试佣金，用独立 SQLite 模拟原账本，不是 BeefAPI 或生产收入证据。BeefAPI HTTP 来源使用真实 global affiliate 可用余额冻结和已提现回写，是另一层独立验收。

## 本地 UI 与权限

仅监听 127.0.0.1，严格校验 Host/Origin，随机 HttpOnly SameSite cookie。拒绝公网监听。测试工作区可操作商家与演示推广者，禁止将其作为公网认证上线。钱包绑定签名包括域名、用户、随机数、链 ID、时间和过期，单次使用。仅本地链模式有测试钱包快捷绑定。

## 验收

| 场景 | 必须证据 |
|---|---|
| 正常自动结算 | 来源冻结、真实本地 EVM 到账、receipt 匹配、来源完成 |
| 相同来源重复/内容冲突 | 同一任务返回同一编号；更换金额/地址拒绝 |
| 成功后重启/回写失败 | 原交易不变，只补回写 |
| RPC 未知/资金不足/明确回滚 | 不误报成功，不释放或重复支付 |
| 冻结与消费竞争 | 同一可用收益只消耗一次 |
| 暂停 | 不发新交易，已广播继续确认 |
| 钱包变更 | 已生成单的收款地址不变 |
| 权限 | 错误令牌/跨 Origin/重放签名被拒绝 |
| UI | 桌面、375/390px 可用，无横向溢出，状态与 API 一致 |
